The pipeline moves out of the skill and into the package. 1.0.x asked a model to copy a 1213-line bash script into every project and to keep 19 invariants intact while doing so; 1.2.0 ships the loop as a Node engine (`bin/pipeline.mjs`, `lib/`), tested once, versioned, and pinned by a small wrapper the project keeps. The skill configures; it no longer generates. The 1.0.17 scenarios are retained against the new engine, with additional coverage for the 1.2.0 behavior.

### Changed

- **Engine in the package.** `auto-develop.sh` is a generated wrapper (`pipeline init`) that execs `npx pi-governance-pipeline@<pin> run`; `PIPELINE_BIN` or `init --local` point it at a checkout. Re-sync is a pin bump. The bundled `assets/` and the copied `.pipeline/lib/` are gone; `lib/governance.mjs` and `lib/gate.mjs` stay argument-compatible for operators and the parity suite.
- **Contract v2.** `contract_version: 2` adds `issues.source` (a checkbox file or a `{ command, trust }` map) and `gates` (an ordered list of `{ name, run }`), so that everything the loop needs is in governance. Both are required in v2; `gates: []` is an explicit choice with a warning. A v1 file keeps every v1 default and its `ISSUE_SOURCE` / `LINT_CMD` / `TEST_CMD` adaptation points, which now override the contract for a run. A decision marker (`[USER DECISION REQUIRED]`) in any field refuses the run with the field named.
- **YAML subset parser** rewritten: block sequences, quote-aware commas and colons (`eslint --ext .js,.ts` survives), named errors for block scalars, anchors, tags. Severity lists may be block sequences.
- **Harness per provider.** `--harness anthropic=claude-code` (or `init --harness …`) routes Anthropic roles through Claude Code, everything else through pi; governance stays harness-neutral. The Claude Code adapter (`-p --output-format json`, `--safe-mode` for reviewers and judges, `acceptEdits` / `bypassPermissions` by the startup gate) is checked against `claude --help` and a stub — no live verification in this release.
- **Role isolation under pi.** Research, reviewers and judges use `--no-approve -ne -ns -np`, overriding saved trust and disabling extension, skill and prompt-template discovery. Research and reviewers have read-only tools; judges have none. All three classes explicitly clear custom system-prompt inputs so global `SYSTEM.md` and `APPEND_SYSTEM.md` cannot enter their prompts. Pi's built-in base prompt, authentication and model configuration remain available; research and judges retain context files, while reviewers use `-nc`.
- **SKILL.md** is three modes in under 80 lines. The operator manual (`references/operations.md`) and the invariants (`references/invariants.md`, INV-01 … INV-29, each with the test that pins it) replace the copies that used to live in `SKILL.md`, `pipeline-template.md` (removed), the audit prompt and the README. `/pipeline-audit` runs `doctor` and reports project-level checks; the loop's invariants are the test suite's job.
- Prompts are templates (`lib/prompts/templates/*.md`) assembled per attempt; the untrusted-input framing and the schemas are harness-owned text.
- `pipeline-guard` reads its patterns and the governance names from `lib/` — the one list that also feeds the diff filter, the stash protection and the integrity snapshot. `/pipeline-status` and `pipeline status` share one implementation.
- Timeouts are native (`ROLE_TIMEOUT_SECONDS` via the child-process timeout); no GNU `timeout` needed. Gates and `!command` sources run through bash where present (`PIPELINE_SHELL` overrides).

### Added

- **Governance integrity.** Governance paths are snapshotted before every tool-bearing role and compared afterwards; a change is restored from the snapshot, costs the attempt, and is logged as `governance-modified`. Covers `eval`, `bash -c` and scripts, which the guard's regexes never could.
- **Split.** The master may answer `split` with two to five sub-issues when the depth is below `max_split_depth` and the issue source can create children (tasks.md can; commands cannot). Children run in the parent's tree with the same budget and attempts of their own; the parent closes when every child is done. `max_split_depth` is no longer a dead contract field.
- **External issue sources** are acknowledged at the startup gate (`--yes` on a non-interactive stdin) before a real run feeds their text into the loop.
- `pipeline init`, `doctor` and `status`.
- `tests/unit/` (`node --test`): parser, contract, gate, master decision, snapshot, harness flags and output parsing, prompt properties, issue sources, status, and a traceability test that checks every invariant names an existing test and every unit test names an invariant. `tests/smoke.sh` gained scenarios for contract gates, v2 refusals, external sources, governance integrity, split, init/doctor and the Claude Code stub; the timeout scenario now exercises the native timeout.
- CI is configured to run both suites on Ubuntu (node 18 and 22) and Windows (node 22).
- Regression tests for commit scope, literal filenames, staged deletions and renames, full and partial implementer self-commits, nested issue files and missing CLI values. Integration tests use the real Pi SDK to validate skill discovery, `/automate` expansion and resource isolation; run them against an installed Pi with `PI_TEST_SDK_DIR`. The smoke suite runs these checks with its SDK install on Node >=22.19; no model calls are needed.
- Opt-in `tests/pi-live.mjs`: packs and installs the artifact in a temporary project, loads its extension through real Pi and exercises the state tool, a reviewer and a tool-free master. Requires `PI_LIVE_MODEL` and makes three billable model calls; excluded from automatic tests and CI.

### Fixed

- **Portable test discovery.** `npm test` uses `node --test` without a directory argument; Node 22 does not accept the `tests/` directory form used in the initial workflow. CI and release publishing share this entrypoint.
- **Windows integrity diagnostics use canonical paths.** Reports remain project-relative when the project or temp directory is reached through a junction, symlink or short-path alias; snapshots and the report now use the same canonical base.
- **Review severity survives mixed JSON schemas.** Critical findings with an off-schema verdict can no longer lose to an empty, well-formed approval in another block. Non-string finding titles no longer crash the severity gate.
- **Commit failures always fail the run.** A failed approval commit exits non-zero even on the last issue; a failed split-parent closing commit halts before the next issue. A halt after the last child leaves its parent open. Approved work and checkbox changes remain available for a manual commit.
- **Approval commits exclude unrelated staged files.** Only reviewed paths and the issue source are committed; previously staged governance or wrapper changes stay in the index. Both ends of a rename are included, including an already-staged deletion.
- **Implementer self-commits stop the run.** A HEAD change blocks the issue before gates or review and prevents subsequent issues from starting, even when some edits remain uncommitted. The `head-moved` event and blocker identify the problem; commits and remaining edits are preserved for inspection.
- **`/automate` forwards all arguments.** Combined options such as `--harness anthropic=claude-code --local` no longer collapse to a bare `--harness`. `init`, `run` and `doctor` reject missing harness values.
- **Research cannot load extensions through saved trust.** Explicit trust and discovery overrides prevent project or global extensions from replacing read tools or running startup hooks in Pi research processes.
- **Global system prompts are excluded from isolated roles.** `--no-approve` alone did not suppress global prompt files. Explicit empty prompt overrides now suppress their discovery; regression checks cover Pi's actual loader and preservation of empty arguments through Windows `.cmd` launchers.
- **Nested issue sources initialize successfully.** `init` creates missing parent directories and validates options and contract before writing or staging setup files.
- `.pipeline/` gitignore probe works before the directory exists (`doctor`, `init`).
- Split children never open a state file of their own; blockers keep naming the tree root.
- Closed from the same-day review of this release (`docs/review-2026-09-05-1.2.0.md`): an interrupted split is resumed at its children instead of implementing the parent again, and `--issue <child>` runs one child under its parent's tree; sub-issue titles are one line and bounded, two to five per split, so a model-authored title cannot write issue lines into `tasks.md`; a role timeout ends the whole process tree and returns within the exit grace period instead of waiting on a grandchild that holds stdout; a `.cmd` harness on Windows is launched through `cmd.exe` with a quoted command line (paths with spaces work, no `shell: true`, no DEP0190); the integrity snapshot compares by hash and spills big files to disk; `research` no longer receives `--approve`; `init` without `AGENTS.md` fails and points at `/govern`; a bad `--harness` is one error line; child ids are the first unused `parent.<n>`; a missing `git` binary is named.
- Closed from the pre-release review (`docs/review-2026-09-05-1.2.0-pre-release.md`): a blocked issue stashes its rejected tree (`pipeline: blocked <id>-<run>`) instead of handing it to the next issue's reviewers and approve commit; a `tasks.md` with CRLF line endings is read and written back unchanged (it used to be "no open issues", exit 0); trust comes from the confirmed `--unattended` flag, and an inherited `PIPELINE_UNATTENDED=1` is dropped with a warning; the integrity snapshot covers the issue source and the wrapper, so an implementer cannot write issues; a harness that exits non-zero is reported with the first line of its stderr, the text is kept as `<answer>.stderr`, and two such implementation attempts are a configuration error instead of six empty-diff retries; gates and `!command` sources are capped by `GATE_TIMEOUT_SECONDS`, and a gate log enters the prompt as head and tail; judges run with `--no-approve -ne -ns -np`, so only implementers are ever trusted; `--harness claude-code` refuses non-Anthropic roles at start and in `doctor`; `init` records the wrapper's executable bit in the index and pins its line endings in `.gitattributes`, and `doctor` warns about a CRLF or non-executable wrapper; issue ids that collide after sanitising are refused; the master's decision word is trimmed; a mapped role without `model` and duplicate YAML keys or nested sequences are contract errors; an issue source outside the repository warns; the guard also catches `wget … | sh`, `git clean -f`, `perl -pi`, `install`, `ln`, `truncate` and `dd of=`; a `#` line inside a blocker no longer splits the entry.
