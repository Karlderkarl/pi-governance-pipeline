Closes two fail-open holes in the review path. `take_over` stashed the project's governance away mid-run, and `capture_diff` dropped every path git chose to C-quote — a changed file could vanish from the diff and from the manifest that claims to account for it, and the run approved the issue anyway.

### Fixed
- **`take_over` stashed the governance, the issue list, and the script itself.** The escalation runs `git stash push -u` to give the stronger model a clean tree, and `-u` takes every untracked path with it. The quickstart in `SKILL.md` commits only `.gitignore`, so in an unmodified setup `AGENTS.md`, `SOUL.md`, `tasks.md` and `auto-develop.sh` are all untracked and all went into the stash. Only `MEMORY.md` was copied out and written back. The run continued — bash holds the script's fd — but every child `pi` after that point loaded its context files from a cwd that no longer had them: reviewers judged the diff with an empty `Project standards:` block, and `mark_issue_done` silently no-opped against a `tasks.md` that was gone. A new `preserve_paths()` names the set (the same one `capture_diff` keeps out of the review diff, plus `ISSUE_SOURCE` and the running script); the stash block copies it to `.pipeline/work/<issue>/pre-stash` and writes it back afterwards. Restore merges into directories rather than replacing them, so no `rm` ever runs on a caller-supplied path.
  - Model routing was **not** affected: `MODELS_JSON` is resolved once at startup, exactly as the comment above `model_for` claims. The `AGENTS.md not found; every role runs the default model` line that appeared after each stash came from the `state escalate` call re-reading the file, and `stateCommand` uses the contract only on `init`. The warning was noise — but it was noise that described a failure mode the script did not have while hiding the one it did.
- **Non-ASCII paths never reached the reviewers.** `core.quotePath` defaults to on, so `git diff --name-only` prints such a path C-quoted (`"\303\234mlaut.md"`), and that quoted form matches no file when it is handed back as a pathspec. Tracked, the per-file diff came back empty and `capture_diff` dropped the row — the file appeared neither in the diff nor under `included` or `omitted`, and because the manifest footer alone kept the patch file non-empty, the caller's empty-diff guard did not fire either: three reviewers approved a diff with `included: (none)` and the issue was marked done. Untracked, the read failed and the reviewers got a new file with a header and no body, listed as `included`. Both listings now use `-z` with NUL records in the intermediate list, the per-file diff pins the path with a `:(literal)` pathspec, an empty result is reported under `omitted` instead of being dropped, and a patch with no diff bytes behind its manifest is written out empty so the existing fail-closed empty-diff path takes it.

### Added
- `tests/smoke.sh` covers both. One project built the way `SKILL.md` says to build it — only `.gitignore` committed — driven through a `take_over`, asserting that `AGENTS.md`, `SOUL.md`, `tasks.md`, `auto-develop.sh` and `MEMORY.md` all survive, that `SOUL.md` still reaches the reviewer prompts after the stash, and that no `AGENTS.md not found` warning appears. One project with a tracked and an untracked non-ASCII filename, asserting that both file contents reach the reviewer prompt and that the manifest names both. The existing `git_init` helper commits the whole seeded tree, which is why neither case was reachable before: it defined the unlucky setup away.

### Changed
- `SKILL.md`'s `compatibility` line said child `pi -p` processes load project-trusted resources "only with a saved trust decision or `--approve`". A global `defaultProjectTrust: always` is a third path (pi `docs/usage.md`), and the line now says so. The README already noted the `ask` default.
