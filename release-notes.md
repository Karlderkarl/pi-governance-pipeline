Closes the findings of the 2026-09-05 review (`docs/review-2026-09-05.md`): two fail-open paths in the review loop, three gaps in the guard and the contract validator, and a set of smaller robustness and documentation issues. Every fix ships with a smoke test that was red before it.

### Fixed
- **A reviewer retry could replace a `critical` with an empty approve.** The one retry for an unparseable reviewer was taken whenever it parsed better than the original — a fresh process with no memory of the first pass, whose clean `{"verdict":"approve","findings":[]}` displaced an original that carried a `critical` behind an off-schema verdict word. The gate then cleared and the issue was marked done. `gate.mjs --check` now prints the worst severity rank the file carries, and the retry is taken only if it parses at least as well **and** is at least as severe. Same direction as everywhere else: strictest wins.
- **Approved work was left uncommitted and bled into the next issue.** The approve branch marked the issue done and returned. With several open tasks, issue B's three reviewers and master judged issue A's diff as part of B, and a `take_over` on B stashed A's approved work away for good while `tasks.md` kept it as done. A new `commit_approved` (marked `ADAPT`) commits exactly the reviewed paths plus the issue source after each approval; `COMMIT_APPROVED=0` or a failed commit stops the run before the next issue and names what was not started. A fresh issue that starts on a tree already differing from HEAD is warned about, with the paths.
- **Severity lists did not have to cover all four severities.** `review: { blocking_severities: [critical], followup_severities: [low] }` validated, and a `high` finding was then neither blocking nor a follow-up: the gate reported `clear`. The validator now requires the two lists to cover `critical`, `high`, `medium`, `low` together (overlap warns), and the gate blocks on a known severity listed in neither, reported under `unlisted_severity`.
- **The guard blocked reads.** Any governance filename plus any `>` on the line counted as a write, so `cat AGENTS.md 2>/dev/null` or `grep … SOUL.md 2>&1` was refused in every non-interactive child — on exactly the files the roles are told to follow. The redirection now has to *target* a governance file, and `mv`/`cp` count only when the governance file is the destination.
- **`AGENTS.override.md` was unprotected.** pi loads it instead of `AGENTS.md`, and the script warns when it exists, but neither the guard (write/edit tools and shell), nor the review-diff filter, nor the take_over stash protection knew the name. All three do now, together with the `AGENTS.MD` / `CLAUDE.MD` spellings; the guard also covers `.pi/settings.json`. The pipeline script itself and the issue source stay out of the review diff as well.
- **The `MEMORY.md` blocker carried the tool log instead of the findings.** On abort the entire `exclusions.md` (lint/test output, master excerpts) went into `MEMORY.md` and back into every later research and implement prompt, uncapped; the gate findings were missing. The entry now carries the findings as prose (no line numbers) and the last 40 lines of the tool log, and the history fed back is capped in bytes (`BLOCKER_HISTORY_MAX_BYTES`, default 16384, newest text kept).
- `take_over` in a repository without a commit: `git stash` refused, the script said nothing, and `implement_master` inherited the rejected tree. A real run now refuses to start without a HEAD (`--dry-run` notes it), and a refused stash is reported on stderr.
- `gate.mjs` no longer dies with a stack trace on `findings: [null]`; non-object entries are dropped.
- `--issue <id>` naming an id that is not open exits non-zero with a message instead of doing nothing with exit 0.
- The validator names the real problem for exactly one mapped `review.*` role ("only one models.review.* role is mapped") instead of reporting a single provider.
- `tests/smoke.sh` picks the newest implement prompt by name (`LC_ALL=C sort`), not by `ls -t`, which is not deterministic on filesystems with coarse mtimes.

### Added
- `tests/guard.test.mjs`: the first behavioural test for `pipeline-guard.ts`. Runs the extension under node's type stripping against stub SDK packages and drives the `tool_call` handler with thirty read, write, destructive and unattended cases. The guard was previously typechecked only.
- Smoke coverage for every fix above: retry-carries-less, two issues with a `take_over` on the second (both committed, nothing stashed away, the second never sees the first's diff), `COMMIT_APPROVED=0` stop, dirty-tree warning, severity partition, `AGENTS.override.md` and the harness kept out of the review diff, missing HEAD, unknown `--issue`, blocker content and byte cap, null findings, one mapped reviewer.
