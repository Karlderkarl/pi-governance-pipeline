## Decisions

- **2026-09-23, 1.2.5: practice findings from a Claude and a Codex review plus a live run.** `init` exits 1 before any write next to a wrapper it would not generate (foreign, other pin, other configuration), because the automate mode runs that script next. Model identity ignores an aggregator route (`openrouter/<vendor>/<model>`), so OpenRouter-only panels count vendors; pi still gets the ref as written. `PIPELINE_GUARD=off` is kept but named by `doctor` and every run — the maintainer's machine has it set user-wide, which silently disabled the guard in every implementer. The govern mode carries its fixed outputs, a contract skeleton and the unattended signal (`PIPELINE_ALLOW_GOVERNANCE_WRITE`) in `SKILL.md`: weaker models (gpt-5-mini) skip the references, and "under `pi -p`" is not observable by a model. The `peerDependencies` upper bound (1.2.4) is replaced by smoke runs against both the newest Pi and the floor; the bound excluded every current Pi while the suite had already broken on 0.87's `loadPromptTemplates` shape.

- **2026-09-09: three corrections to the hardening above.** (1) `hasWrapperEolRule` required the wrapper rule to be the last line of `.gitattributes`. Appending an unrelated `*.md text` — which cannot match `auto-develop.sh` — then produced a WARN on a correct setup and a duplicate rule on the next `init`. The first attempt at this — "the last rule naming the wrapper" — reintroduced the hole it was meant to leave alone: a later `*.sh text eol=crlf` does match the wrapper, and `check-attr` cannot be the second opinion because `.git/info/attributes` outranks `.gitattributes` and is exactly the private file that does not survive a clone. Splitting permanence and effectiveness between a text test and `check-attr` is not enough; hand-rolling glob semantics would have been the third wrong answer. `hasWrapperEolRule()` now copies the project's `.gitattributes` into a scratch repository and asks git to resolve it there, so git's own matcher decides which later patterns matter. Both directions are pinned in one test, because fixing either one broke the other. (2) The `unprocessed_review` marker was fed to the implementer through `findingsToProse`, telling it to "return complete review JSON" — an instruction addressed to the reviewer that no implementation can follow, and over repeated attempts the only feedback it received. Filtered out; the gate JSON and the run log keep it. (3) The marker blocks the attempt and survives a retry by design, but a reviewer quoting a `"severity"` line out of the diff triggers it, and left alone that spent the whole tree budget on a formatting problem. Two consecutive attempts carrying it now end the issue as a configuration error, like a panel below the floor; the check runs before the `MIN_REVIEWERS` streak because its cause is the more specific one. The reviewer prompt also asks explicitly not to quote JSON out of the diff. Regressions in `tests/unit/review-2026-09-09.test.mjs` with `tests/fixtures/quoting-reviewer-stub.mjs`; all three fail without the fixes.

- **2026-09-09: unprocessed reviewer evidence blocks the attempt, and LF setup is portable.** A lost panel seat still allowed approval with two other reviewers. Unconsumed severity keys and exhausted JSON scans now produce an `unprocessed_review` finding, which the unknown-severity gate blocks in every partition and which survives a clean retry. Complete findings recovered from a broken review envelope are retained without granting a panel seat. JSON spans are treated as consumed only when their relevant keys were actually handled; master decisions use the same check. `init` keeps an explicit final wrapper rule in the project's `.gitattributes`, verifies effective private overrides, and handles a missing attributes file before Git initialization. A private `.git/info/attributes` LF rule cannot replace the project rule or mask a conflicting earlier project rule. Regressions: `tests/unit/review-safety.test.mjs` and `tests/fixtures/unprocessed-review-stub.mjs`; all seven new tests failed on the previous implementation. Validation: 173 tests with the real Pi SDK, no skips; full smoke suite with real SDK types from the local npm cache; git diff --check.

- **2026-09-09: the free-standing-JSON fix needed a second pass.** The first scanner carried brace and quote state through the whole answer, so prose was enough to hide the object again — `if (authorized) {` in a sentence opens a level the object nests inside, and one unmatched `"` swallows its braces. Both reproduced end-to-end as an approval and a commit. Every `{` is now its own start with fresh state, parsed spans are skipped, and there is a bound on starts. The fail-closed half is new and covers what no scanner can promise: a `"severity"` key that no parsed object holds costs the reviewer its panel seat (folded into `invalidFindings`, so the retry and the evidence rules already applied), and a `"decision"` key likewise turns the master's `approve` or `split` into `reject`. Reviewer and master path have separate end-to-end regressions — a pass on one was covering the other. Lesson recorded: the first fix was verified only against the reported shape, not against the class.

- **2026-09-09: the LF pin is checked as `text` and `eol`, repository-only.** `eol=lf` alone proves nothing — `-text eol=lf` resolves eol to lf and normalises nothing, and `doctor` reported PASS for it. A rule that lived only in the user's `core.attributesFile` also made `init` skip writing the project's own, so the pin did not travel with a clone. `wrapperEol()` in `lib/cli/wrapper.mjs` now asks `git -c core.attributesFile= check-attr text eol` and both `init` and `doctor` use it.

- **2026-09-09: free-standing JSON is a review candidate (critical).** A reviewer or master that wrote one object as plain text and repeated it in a code fence lost the free one entirely: the only candidate that could hold it was the whole text, and `tryParseObject` cuts that from the first `{` to the last `}` — across both objects, so it never parsed. Reproduced end-to-end: three reviewers reporting `critical`, a master writing `reject`, and the pipeline approved, closed the issue and committed the diff with exit 0. `jsonCandidates` now also yields every balanced top-level object, quote- and escape-aware; the scan only adds candidates, and by strictest-wins an extra candidate can raise severity but never lower it. INV-18's promise ("findings from all non-echo JSON candidates are retained") was the thing being violated. Regression runs to the commit decision, not only over the parser: `tests/unit/review-2026-09-09.test.mjs` with `tests/fixtures/mixed-json-stub.mjs`.

- **2026-09-09: the wrapper's LF pin is checked with `git check-attr`.** `init` read any line starting with `auto-develop.sh ` as a line-ending rule, so `linguist-generated=true` pinned nothing while `text eol=crlf` and `-text` pinned the opposite — and it reported success in all three cases. It now asks git what it resolves, appends the rule when that is not `lf` (a later line wins in the same file), and FAILs when an override lives in another `.gitattributes` or the global one. `doctor` gained the matching check.

- **2026-09-09: `--auto-merge` no longer grants implementer trust.** It is still confirmed at the startup gate as the adaptation point for a real merge step, but `--approve` / `bypassPermissions` now comes from `--unattended` alone. Granting trust was the flag's only actual effect, which contradicted its own `run --help` line ("parsed and confirmed, not implemented") and made a flag named after merging the shortest route to a fully trusted implementer. INV-08 changed with it. Regression: `tests/unit/review-2026-09-09.test.mjs`.

Also: UTF-8-safe truncation for the diff and the reviewer JSON, `peerDependencies` pinned instead of `"*"`, `--tools` appended last in the Claude Code adapter (it is variadic), and the manifest siblings of a throwaway capture cleaned up. ## Drift notes

- **PRD AK6 is met with a stub, not live.** The Claude Code adapter runs the scenario table against a stub `claude` and its flags are checked against `claude --help`. No live run against Claude Code has been made in this release.
- **`govern` has no eval.** Nothing is generated any more except governance itself; whether an agent following `SKILL.md` writes a sound contract from a PRD is still unmeasured. `init`/`doctor` refuse a bad one, which is the safety net, not a measurement.
- **The parity suite is bash.** `tests/smoke.sh` needs bash (Git Bash on Windows); unit tests that run shell commands also need bash on PATH or `PIPELINE_SHELL`. Porting the scenarios to `node --test` was deferred on purpose: the bash suite is the proof that 1.2.0 retains the 1.0.17 scenarios. CI covers Ubuntu Node 18/22 and Windows Node 22; the release process waits for that matrix before pushing the tag, then reruns both suites before OIDC publishing.
