# Release review 1.2.1 — 2026-09-05

## Scope and result

Review of the skill-slimming patch against `v1.2.0`, including slash prompts,
reference routing, documentation, packaging and tests. All 42 tracked files in
`bin/`, `lib/` and `extensions/` are unchanged from 1.2.0. The version and wrapper
fixture pin move to 1.2.1; there is no engine or guard behavior change.

Pi 0.85.1 reviewed the actual patch and repository using
`openrouter/openai/gpt-5-mini:high`, in fresh, read-only processes with
`read,grep,find,ls`. Project trust, extensions, skills, prompt-template discovery,
context-file discovery and custom system-prompt discovery were disabled. The
skill files were review input, not instructions to run govern or automate.

The first Pi pass approved with three low-severity notes. After the corrections
and checks below, a second fresh pass returned `approve` with `findings: []`.
No unresolved release-review finding remains.

## Findings and disposition

| Finding | Disposition |
|---|---|
| Repository-only prompt-design documentation needs a discoverable location for npm users. | Kept it out of the skill context as intended; README now links directly to the version-pinned GitHub document. |
| Pi SDK tests checked only the Node major, although Pi 0.85 needs Node >=22.19. | Fixed the major/minor check. A regression reproducing the previous major-only behavior failed for Node 22.0; the corrected boundary test covers 18, 20, 22.0, 22.18, 22.19, newer 22, 24 and 26. These are version-gate cases, not live runs on every listed runtime. |
| Short slash prompts could lose the operational checklist unless the skill retains it. | Verified that Mode: automate still owns init, argument forwarding, dry-run, output reporting, contract-error handling and HEAD/startup prerequisites. No duplicate checklist was reintroduced. Real Pi template loading/expansion and init behavior are covered by the SDK tests. |

The local review also corrected an inherited documentation inaccuracy: reviewers
receive the same first 120 lines of `SOUL.md`, with separate focus instructions,
not different role-specific excerpts. The implementation was already correct.

`skill-creator` guided the review toward essential constraints and mode-specific
references; the slimming remains intact. Its Codex-specific quick validator
rejects the existing Pi `compatibility` frontmatter field. The native Pi skill
loader accepts the skill without diagnostics; the valid Pi field is preserved.

## Limits and publication gate

The two Pi release reviews are static. The live fixture checks provider
authentication and integration, not a full multi-provider implementation run,
panel independence or general governance-generation quality. Claude Code remains
stub-verified only. No user project or global Pi installation was changed by the
live fixture.

Publication uses the existing CI/release workflows: the complete Node 18/22 Linux
and Node 22 Windows matrix must pass before tagging. The tag-triggered release
workflow reruns tests, publishes to npm through Trusted Publishing, then creates
the GitHub Release from the version-matched release notes.
